# Редизайн фронтенда spin.clinic: библиотека компонентов + Framer Motion

## Context

spin.clinic — польский архив/агрегатор источников (Next.js 14 App Router + Django). Текущий фронтенд намеренно «газетный»: у главной карточки `.material-box` нет скругления вообще, размеры жёстко заданы `184×120px`, типографика опускается до 7–9.5px, тени подавлены (`.shadow-sm { box-shadow: none }`), три темы с янтарным акцентом. Анимации — почти весь рукописный CSS; framer-motion установлен, но задействован ровно в одном файле.

Владелец хочет другой визуальный продукт: вид в духе USA Today (референс приложен) — скруглённые карточки с изображениями, синий акцент, чистая иерархия. Плюс янтарное свечение с левитацией при наведении, эффект портала (карточка перетекает в полноэкранный режим) и — главное — **сплошное движение: любое действие пользователя где угодно (портал, дашборд, публичные страницы) перетекает, а не переключается.** Сайт должен ощущаться непрерывным и живым, без единого мгновенного скачка состояния.

Результат этапа: система движения плюс библиотека элементов (4 вида карточек новостей, кнопки, дропдауны, меню, футер) в новом визуальном языке, показанная на витрине. Применение системы ко всем существующим поверхностям — **следующий этап**, после утверждения вида.

## Подтверждённые решения владельца

| Вопрос | Решение |
|---|---|
| Бренд | **Заменить полностью.** Две темы (ночная/дневная), чёрный/белый + синий акцент, скруглённые карточки |
| Объём этапа | **Сначала библиотека + витрина**, главная — этап 2 |
| Эффект портала | **Морфинг на месте** (`layoutId`) + `history.pushState` на `/material/[id]` |
| Язык интерфейса | **Польский** |
| Наведение | Свечение позади элемента + лёгкая левитация над поверхностью. **Уточнение 23.09: янтаря в системе нет вообще — свечение и подкраска кромки синие**, из акцентной палитры. Упоминания «янтарного» ниже читать как «синее» |
| Движение | **Сплошное.** Каждое действие на любой поверхности — портал, дашборд, публичные страницы — перетекает. Ни одного мгновенного скачка состояния |

## Roadmap для параллельных агентов

Документ ниже — спецификация. Этот раздел — операционный план: как разложить её на независимые пакеты работы, чтобы несколько агентов делали их одновременно, не мешая друг другу, и чтобы результат сложился в одно целое.

### Принципы разбиения

1. **Непересекающееся владение файлами.** Каждый пакет владеет своими файлами и не трогает чужие. Единственные общие файлы — `kit/index.ts` и оболочка витрины — принадлежат интегратору; исполнители ничего в них не пишут, а поставляют собственный файл раздела витрины и список экспортов.
2. **Контракты раньше кода.** Интерфейсы между пакетами (имена пружин, токенов, пропсы `Button`, `NewsCard`, API портала, фикстуры) фиксируются интегратором в волне 0 и после этого **не меняются исполнителями**. Нужно изменить контракт — исполнитель пишет это в отчёте, решает интегратор.
3. **Волны по зависимостям.** Пакет стартует, когда его входы уже смержены. Внутри волны пакеты независимы и идут параллельно.
4. **Каждый агент — в своей ветке и worktree** (`kit/r1-icons-controls`, …). Мержит интегратор; при непересекающемся владении конфликтов не будет по построению.
5. **Модели.** Хорошо специфицированные пакеты с чёткими границами — Sonnet 5. Два пакета с наибольшим сквозным риском — интеграция (R0) и портал (R5) — стоит отдать сильной модели: там ошибка стоит дороже экономии. Это рекомендация, решение за владельцем.

### Контракты (фиксирует R0 в волне 0)

Это то, что все исполнители читают до начала работы и на что опираются без переспрашивания.

**Пружины** — `kit/motion/springs.ts`, имена: `ui · press · move · fade · portalIn · portalOut · scrim · sheet · settle · expand · collapse · reduced`. Значения — в таблице раздела «Пружины». Других имён нет.

**`useMotionTokens()`** возвращает `{ reduced, t(name, overrides?), stagger, staggerCap, rise, scale(v), gestures, morph }`. Компоненты берут переходы только через `t()`, никогда не пишут `transition` литералами.

**Токены CSS** — только с префиксом `--sc-`. Полный список имён — в `kit.css` после волны 0; исполнитель не добавляет новых глобальных токенов, только локальные переменные внутри своего блока с префиксом своего компонента (`--sc-btn-*`).

**Классы** — только с префиксом `sc-`, БЭМ-подобно: `sc-card`, `sc-card__media`, `sc-card--large`. Состояния — `data`-атрибуты (`data-size`, `data-state`), не классы-модификаторы.

**`Button`** — пропсы из раздела «Компоненты»; `Dropdown`, `NavMenu`, `SiteFooter` используют его как есть, не рисуют свои кнопки.

**`Dropdown`** дополнительно получает `presentation: 'popover' | 'sheet' | 'auto'` — при `auto` ниже 481px рендерится нижним листом (компонент листа — R7, до его готовности R2 реализует `popover` и заглушку `sheet`, отрисовывающую popover; R7 подменяет).

**`NewsCard`** — пропсы из раздела «Компоненты» плюс `expandable?: boolean` (ступени A/B) и `onOpen`. **Правило владения `layoutId`:** в любой момент у материала ровно один элемент с `layoutId={`sc-card-${id}`}` — либо карточка, либо её клон-предпросмотр в слое портала (если он есть), либо оверлей. Карточка снимает с себя `layoutId`, когда клон или оверлей его несёт. Это правило исключает двойные морфинги.

**Портал** — `PortalProvider` даёт `usePortal(): { active, isActive(id), open(article, originEl), close(), originRef }` и `historyMode: 'none' | 'query' | 'path'`. Витрина работает в `query`; `path` — этап 2.

**Фикстуры** — `showcase/fixtures.ts` экспортирует `makeArticle(overrides)` (возвращает полный `Article`, все обязательные поля заполнены), `FIXTURE_ARTICLES` (24 штуки с длинными польскими строками, отрицательные `id`, `przyklad.invalid`), `makeArticles(n, seed)` для замеров на 200+, `FIXTURE_STRIPS` (5 полос по 8 карточек). Изображения — `data:image/svg+xml` со словом DEMO.

**Раздел витрины** — файл `showcase/sections/<Имя>.tsx` экспортирует `export const meta = { id: 'buttons', title: 'Przyciski' }` и `export function Section()`. Раздел сам показывает **все** состояния своего компонента в обеих темах и не зависит от других разделов.

### Общие правила для каждого агента

Каждый исполнитель получает этот документ целиком (интегратор кладёт его в репозиторий как `docs/UI_KIT_PLAN.md`), список «своих» разделов и этот блок правил:

1. Читать: «Ключевое решение об изоляции», «Ловушки каскада», «Дизайн-токены», «Шрифт», «Типографическая шкала», «Отступы», «Сплошная система движения», свои разделы из «Оживление каждого элемента», «Контракты». Остальное — по потребности.
2. **Ни одной утилиты Tailwind** в компонентах библиотеки. Только классы `sc-`. Причина — в «Ловушках каскада».
3. **Не трогать** `globals.css`, `packages/ui/src/components/**`, `backend/**`, `layout.tsx`, `providers.tsx`, `kit/index.ts`, оболочку витрины. Нужен экспорт или подключение — написать в отчёте.
4. Переходы — только через `useMotionTokens().t()`. Анимировать только `transform` и `opacity`. Не добавлять `will-change`. Не использовать `transition: all`.
5. Каждое состояние доступно с клавиатуры и читается без цвета. Минимум касания 44px. Кольцо фокуса — `--sc-focus`, специфичность `0,2,0`.
6. Уменьшенное движение — не «ничего», а короткое затухание. Структуру разметки на `reduced` не ветвить (гидратация), ветвить только значения.
7. Интерфейс по-польски. Фикстуры — только из `fixtures.ts`, свои данные не выдумывать; заголовки описывают раскладку, не события.
8. Готово значит: `pnpm --filter frontend-spin build` и `typecheck` зелёные; раздел витрины показывает все состояния в обеих темах; проверено с клавиатуры и при `prefers-reduced-motion`; в отчёте — список экспортов, отклонения от спецификации и вопросы к контрактам.

### Брифы по ролям

**R0 — Интегратор (волна 0, затем мерж и волна 4).** Поднять окружение (corepack → pnpm 9, `install`, базовая сборка на нетронутом коде, `pnpm dev:spin` постоянно). Скопировать план в `docs/UI_KIT_PLAN.md`. Создать `kit.css` с полным набором токенов обеих тем, подключить Montserrat через `next/font` с `latin-ext`, написать `springs.ts`/`physics.ts`/`useMotionTokens`/`MotionRoot`, `fixtures.ts`, оболочку витрины с переключателем темы (только `dataset.theme`, с восстановлением) и принудительными режимами доступности, раздел «Токены» и «Типографика», маршрут `app/ui-kit/page.tsx`, `MotionRoot` в `providers.tsx`, подпуть `./kit` в `package.json`. **Шлюз волны 0**: сборка зелёная, `/` не изменилась, диакритика в Montserrat, синее кольцо фокуса на тестовой карточке токенов, морфинг тестового блока через портал из контейнера с `overflow-x: auto` работает (шаг 3 порядка работы — проверить до старта R5). Затем: принимать пакеты, вписывать разделы в оболочку и экспорты в `index.ts`, мержить.

**R1 — Иконки и контролы (волна 1).** Читает «Каталог иконок», «Селекторы, флажки и переключатели», «Формы и поля ввода». Реализует набор иконок по каталогу (сетка 24, штрих по размеру, `currentColor`, `aria-hidden` по умолчанию, морфинги `menu↔close`, `sun↔moon`, `eye↔eye-off`, прорисовка `check`), и пять контролов со всеми состояниями. Однократный блик `--sc-sheen`. Раздел витрины: иконки в трёх размерах × две темы; контролы сеткой состояний. Не делает: кнопок, дропдауна.

**R2 — Кнопки и дропдаун (волна 1).** Читает «Компоненты» (Button, Dropdown), «Каталог кнопок», «Кнопка», «Дропдаун» из оживления. `Button` со всеми вариантами, размерами, формами, `loading` без изменения ширины, `href` → `next/link`, зона нажатия 44px. `useDismissable`. `Dropdown` в трёх режимах с полной клавиатурой, `transform-origin` от триггера, переворот вверх у нижнего края, `presentation` с заглушкой `sheet`. Раздел витрины — матрица по каталогу кнопок, все состояния каждой. Не делает: иконок (берёт из R1 — до его мержа использует временные инлайновые SVG в своём файле и меняет на импорт при интеграции), нижнего листа.

**R3 — Карточка (волна 1).** Читает «Компоненты» (NewsCard), «Карточка новости», «Три ступени», «Ступень B», «Наведение: свечение и левитация», «Типографика». Один компонент, четыре размера через `data-size`, шесть состояний данных, ступени A и B **в обычной сетке** (в лентах B делает R5 — R3 оставляет проп `expandable` и колбэк, через который R5 подхватит), свечение через `::before`, левитация по размеру, `drop-shadow` на тексте `large`, `tabular-nums` в мете, `<time>` только при настоящей дате, никакого пустого `src`. Раздел витрины: 4 × 6 матрица, ряд бейджей, `large` в `stack` и `split`, ряд ступеней A/B с регулятором bounce. Не делает: портала, карусели.

**R4 — Примитивы движения и жесты (волна 1).** Читает «Сплошная система движения», «Списки, сетки и ленты», «Загрузка», «Перетаскивание полос», «Закрытие перетаскиванием» из «Портал», «Бюджет производительности». Шесть примитивов, `ReorderableStrips` на `Reorder` с ручкой, долгим нажатием, автопрокруткой, клавиатурой и `aria-live`, сохранением в `localStorage` и явной подписью «на этом устройстве». Три хука: `useDragDismiss` (проекция, знак скорости, передача скорости на возврате), `useScrollLock` (компенсация полосы, `useLayoutEffect`, гашение `scroll-behavior`), `useModalA11y` (`inert`, ловушка, возврат фокуса в `onExitComplete`). Раздел витрины: живой список с кнопками, табы с индикатором, счётчик, скелет → контент, пять перетаскиваемых полос, стенд `useDragDismiss` с выводом скорости и решения. Не делает: портала — только хуки для него.

**R5 — Портал (волна 2, сильная модель).** Читает весь раздел «Портал» из оживления, «Раскрытие карточки по клику», «Ступень B» (часть про ленты), «Адрес», «Бюджет производительности», «Риски» целиком. `PortalProvider` с двумя контекстами (API и состояние), `PortalLayer` через `createPortal` в `body` с постоянно смонтированным `AnimatePresence`, `useHistoryPortal` с `owned`-ref, сохранением `search`, `replaceState` для связанных, режимами `none/query/path`. `MaterialSurface` с `mode: 'page' | 'overlay'` (содержимое: медиа, заголовок, источник со **ссылкой на оригинал**, дата, категория, описание, связанные карточки лентой, поделиться, избранное). `useHoverExpand` — ступень B через клон в слое портала для лент, с правилом владения `layoutId`. Три случая возврата. Раздел витрины: карточки в сетке и в ленте с `overflow-x: auto`, кнопки «размонтировать исходную карточку», «прокрутить её из вида», проверка непрерывности «клик по развернутой». Не делает: мобильного листа.

**R6 — Навигация и футер (волна 2).** Читает «Компоненты» (NavMenu, SiteFooter, ThemeToggle), «Меню и шапка», «Футер», «Переходы между страницами», «Смена темы». `NavMenu` с переезжающим индикатором, сентинелом для кромки, мобильной шторкой; `SiteFooter` с колонками-`nav`; `ThemeToggle` день/ночь/авто — **на витрине меняет только `dataset.theme`**, честный `auto` через `matchMedia`, класс плавного перехода цвета на `<html>` на время переключения; `app/ui-kit/template.tsx`. ## Ключевое решение об изоляции

Библиотека строится в **отдельном пространстве имён `sc-`** (`--sc-*` переменные, `.sc-*` классы), а `frontend-spin/app/globals.css` на этом этапе **не меняется ни одной строкой**.

Причина принципиальная: 24 переменные тем на строках 2–4 читают все 57 существующих компонентов. Поменять `--color-primary` на синий — значит перекрасить живую главную страницу сегодня, а это ровно то, что отложено на этап 2. Отдельное пространство имён даёт нулевой радиус поражения: ни одна из 1603 строк не читает `--sc-*`.

По той же причине на этом этапе **не трогаем** `ThemeSwitcher.tsx`, `localStorage['spin-theme']`, скрипт против FOUC и тему `pastel`. В библиотеке `pastel` просто ссылается на дневной набор токенов, чтобы новые компоненты никогда не выглядели сломанными. Удаление pastel из живого переключателя — этап 2, вместе с переводом главной: иначе пользователь потеряет свою тему на сайте, который ещё выглядит по-старому.

## Шрифт: Montserrat

Montserrat заменяет суперсемейство IBM Plex. Это геометрический гротеск с крупной высотой строчных — он читается крупнее своего кегля, хорошо держит широкие прописные в бейджах и даёт тот «чистый» вид, что в референсе.

**Подключение** — через `next/font/google`, а не `@fontsource`, как остальные шрифты в проекте:

```ts
import { Montserrat } from 'next/font/google';
const montserrat = Montserrat({
  subsets: ['latin', 'latin-ext'],   // latin-ext обязателен
  variable: '--font-montserrat',   // класс с этой переменной вешается на <html>; токен --sc-font-sans ссылается на неё
  display: 'swap',
  axes: ['wght'],                     // переменная ось веса: один файл на все веса
});
```

- **`latin-ext` не опционален.** Польские `ą ć ę ł ń ó ś ź ż` живут именно там. Без этого поднабора диакритика подменится запасным шрифтом, и текст поедет по ширине и цвету — самая частая и самая заметная ошибка в этом проекте.
- **Переменная ось веса** — один файл вместо шести статических начертаний.
- `next/font` самостоятельно хостит файл и резервирует метрики, поэтому скачка раскладки при загрузке нет.
- Подключение переменной **не меняет живые страницы**: `body { font-family }` в `globals.css` остаётся нетронутым, Montserrat применяется только там, где используется `--sc-font-sans`. Изоляция сохранена.

**Чего у Montserrat нет и чем это закрывается.** У семейства нет ни антиквы, ни моноширинного начертания.

- **Антиква не нужна вовсе.** Старый бренд отдавал ей заголовки нитей; новый вид полностью гротескный, как в референсе. Одно семейство — одна интонация.
- **Моноширинное заменяется цифрами фиксированной ширины.** В проекте моноширинный нёс смысл, а не декор: источник, время, даты, счётчики и доказательный след должны выравниваться в колонку. Это даёт `font-variant-numeric: tabular-nums`, который Montserrat поддерживает, — без второго семейства и без лишних килобайт.
- Системный `ui-monospace` остаётся **только** для настоящих идентификаторов и адресов, где важно различать `0/O` и `1/l/I`. Нулевой вес, потому что системный.

```css
--sc-font-sans: var(--font-montserrat), system-ui, sans-serif;
--sc-font-mono: ui-monospace, SFMono-Regular, Menlo, monospace;
```

Голые `--font-serif` / `--font-mono` **не трогаем**: они используются в 9 местах, но нигде не определены, и их определение перекрасит живые страницы.

**Что проверить на витрине именно из-за Montserrat.** Он заметно шире IBM Plex Sans при том же кегле. Польские заголовки длинные (`Rzeczpospolita`, `parlamentarny`, `sprawiedliwości`), а карточка `mini` узкая — поэтому фикстуры обязаны содержать реально длинные польские строки, а не короткие заглушки. Если переносы окажутся плохими, правим кегль заголовка карточки, а не ширину карточки.

## Типографическая шкала

Трекинг зависит от кегля — одно значение на все размеры неверно всегда. Геометрический гротеск при увеличении выглядит разреженным, поэтому крупный текст поджимается сильнее, чем у гуманистических гротесков; мелкий, наоборот, требует разрядки.

| Токен | Кегль | Интерлиньяж | Трекинг | Вес | Назначение |
|---|---|---|---|---|---|
| `display` | 34–56 `clamp` | 1.06 | `−0.030em` | 700 | заголовки разделов витрины, герой |
| `title-l` | 26 | 1.16 | `−0.022em` | 700 | заголовок большой карточки, заголовок оверлея |
| `title-m` | 20 | 1.24 | `−0.016em` | 600 | заголовок средней карточки |
| `title-s` | 16 | 1.30 | `−0.010em` | 600 | заголовок компактной карточки |
| `title-xs` | 14 | 1.34 | `−0.006em` | 600 | заголовок миниатюры |
| `body` | 15 | 1.60 | `0` | 400 | проза, описания, футер |
| `body-s` | 13 | 1.52 | `+0.004em` | 400 | описание в карточке |
| `meta` | 12 | 1.40 | `+0.012em` | 500 | источник · дата, `tabular-nums` |
| `caption` | 11 | 1.34 | `+0.045em` | 600 | бейджи, надзаголовки, ПРОПИСНЫЕ |

**Минимальный кегль в библиотеке — 11px.** Нынешние 7px, 8px и 9.5px в `globals.css` — главная потеря читаемости, которую мы оставляем позади.

Дополнительно: `font-optical-sizing: auto`; `tabular-nums` на всём, что содержит время, даты и счётчики, иначе числа «дышат» при обновлении; длина строки прозы ограничена `65ch` — при большей мере глаз теряет начало следующей строки.

### Типографика для каждой цветовой версии

Одна и та же шкала в двух темах выглядит по-разному, и это не вкусовщина, а оптика: **светлый текст на тёмном фоне кажется жирнее**, чем тёмный на светлом при том же начертании. Свечение вокруг светлых штрихов визуально «раздувает» их и заодно подзакрывает внутрибуквенные просветы. Если не компенсировать, ночная тема выглядит грузной и грязной, а дневная рядом с ней — бледной.

Компенсация в ночной теме:

| Что | День | Ночь | Почему |
|---|---|---|---|
| Вес крупного текста (`display`, `title-l`) | 700 | **600** | на тёмном 700 читается как 800 и «залипает» |
| Вес средних заголовков (`title-m/s/xs`) | 600 | **500** | то же, слабее |
| Вес основного текста | 400 | **400** | остаётся; ниже 400 Montserrat на тёмном начинает «рассыпаться» |
| Трекинг мелкого текста (`meta`, `caption`) | как в шкале | **`+0.006em` сверх** | просветы подзакрываются, нужна разрядка |
| Трекинг крупного | как в шкале | **без изменений** | на больших кеглях эффект незначим |
| Цвет основного текста | `#0B0C0E` | `#F5F5F7` | ни чистого чёрного, ни чистого белого: контраст 21:1 даёт резь и ореол |

Реализуется переопределением тех же переменных внутри блока ночной темы — то есть компонент по-прежнему знает только `var(--sc-t-title-l-weight)` и ничего не знает о теме:

```css
:root, html[data-theme="dark"] {
  --sc-w-display: 600; --sc-w-title: 500; --sc-w-body: 400;
  --sc-track-small: 0.018em;   /* meta: 0.012 + 0.006 */
}
html[data-theme="light"], html[data-theme="pastel"] {
  --sc-w-display: 700; --sc-w-title: 600; --sc-w-body: 400;
  --sc-track-small: 0.012em;
}
```

При переключении темы веса и трекинг меняются вместе с цветом. Поэтому переход темы делается плавным по цвету, но **вес и трекинг переключаются мгновенно** — анимировать вес переменного шрифта означает пересчёт глифов на каждом кадре, а выигрыш нулевой.

## Отступы, сетка и ритм

Шаг 4px. Именованная шкала, чтобы в компонентах не появлялись случайные 7 и 13 пикселей, которыми сейчас полон `globals.css`:

`1:4 · 2:8 · 3:12 · 4:16 · 5:20 · 6:24 · 7:32 · 8:40 · 9:48 · 10:64 · 11:80`

**Внутренние отступы компонентов** — пропорционально размеру, чтобы скругления оставались концентрическими:

| Элемент | Отступ | Радиус | Внутренний радиус медиа |
|---|---|---|---|
| карточка `mini` | 10 | 18 | 10 |
| карточка `compact` | 12 | 18 | — (медиа во всю ширину) |
| карточка `medium` | 14 | 22 | — |
| карточка `large` | 18 | 28 | — |
| кнопка `sm / md / lg` | 12 / 16 / 20 по горизонтали | 10 / 14 / 14 | — |
| панель дропдауна | 8 | 22 | пункт 14 |
| оверлей портала | 24 (мобильный 16) | 0 в развёрнутом виде | — |

**Сетка и контейнеры.** Максимальная ширина контента 1280px (как сейчас), боковые поля `max(16px, (100vw − 1280px) / 2)`. Межколоночный интервал 16px до 900px, 20px выше. Колонки: 1 до 640, 2 до 900, 3 до 1280, 4 выше — для карточек `medium`.

**Вертикальный ритм.** Между секциями 48px, на мобильном 32px. Между заголовком секции и содержимым 16px. Внутри карточки: медиа → заголовок 12px, заголовок → описание 8px, описание → мета 12px (мета прижата книзу через `margin-top: auto`, чтобы у карточек разной высоты в одном ряду мета выравнивалась).

**Правило переиспользования:** любое расстояние в компоненте берётся из шкалы. Значение вне шкалы — повод исправить шкалу, а не написать число.

## Наведение: свечение и левитация

Системный приём, единый для всех элементов — карточек, кнопок, пунктов меню, ссылок футера.

Янтарь возвращается, но **только как свет**: он никогда не используется как заливка, текст или бейдж. Роль акцента остаётся за синим, янтарь отвечает за подсветку. Так два цвета не конкурируют.

Реализация — отдельный слой позади элемента, а не анимация `box-shadow` (тень не уходит в композитор и роняет плавность):

```css
.sc-hoverable { position: relative; isolation: isolate; }
.sc-hoverable::before {
  content: ''; position: absolute; inset: -6px; z-index: -1;
  border-radius: inherit; background: var(--sc-glow);
  filter: blur(var(--sc-glow-blur));
  opacity: 0; transform: scale(.96);
  transition: opacity var(--sc-dur-base), transform var(--sc-dur-base);
}
@media (hover: hover) {
  .sc-hoverable:hover::before { opacity: 1; transform: scale(1); }
}
.sc-hoverable:focus-visible::before { opacity: 1; transform: scale(1); }
```

Анимируются только `opacity` и `transform` — обе свойства композитора.

**Левитация** — подъём плюс углубление тени, величина растёт с размером элемента (крупная поверхность должна читаться как более «толстая»):

| Элемент | Подъём | Тень |
|---|---|---|
| кнопка, пункт меню, ссылка | `−1px` | `e-1 → e-2` |
| карточка mini / compact | `−2px` | `e-1 → e-2` |
| карточка medium | `−3px` | `e-1 → e-2` |
| карточка large | `−4px` | `e-2 → e-3` |

Подъём и свечение — на пружине `ui`, нажатие — на `press` (имена из канонической таблицы пружин ниже); отклик начинается по `pointerdown`/`pointerenter`, а не по отпусканию.

Обязательные оговорки:

- **Клавиатура получает то же самое.** Всё, что даёт `:hover`, даёт и `:focus-visible` — иначе клавиатурный пользователь второсортен.
- **`@media (hover: hover)`**, чтобы на тач-устройствах состояние не «залипало» после тапа.
- **Уменьшенное движение**: свечение остаётся (изменение прозрачности не вестибулярно), левитация отключается — ровно как рекомендует Apple для reduce.
- **Свечение только позади.** Слой лежит на `z-index: -1` под содержимым, контраст текста не трогает.
- **В дневной теме янтарь по белому почти не читается** (2.2:1 как цвет). Это ожидаемо: свечение физически работает на тёмном. Поэтому днём подъём несут в основном тень и кромка, а свечение приглушено; ночью — наоборот. Тюнится отдельно на витрине, не одним значением на обе темы.

## Компоненты

**Карточка — один компонент `NewsCard` с пропом `size`, а не четыре компонента.** Все размеры едят один и тот же `Article` и делят именно сложную часть: пустой `image_url`, даты `null`/`'undated'`/`'unknown'`, свободная строка `category`, ветвление по `date_precision`, приём «растянутой ссылки». Четыре копии — четыре расхождения; в репозитории это уже произошло между `MaterialBox` и `ArticleCard`, у них несовместимая обработка отсутствующей картинки. Плюс контейнерам нужно менять размер отзывчиво — это один проп вместо условного рендера на каждом вызове.

```ts
type NewsCardProps = {
  article: Article;
  size?: 'mini' | 'compact' | 'medium' | 'large';   // по умолчанию 'compact'
  href?: string;                                     // по умолчанию /material/${id}
  headingLevel?: 2 | 3 | 4;                          // вызывающий владеет структурой заголовков
  showCategory?: boolean; showDescription?: boolean;
  eyebrow?: ReactNode;                               // «DEMO», «TOP 10»
  action?: ReactNode;                                // избранное — вне ссылки
  onOpen?: (article: Article) => void;               // портал; без него обычный <Link>
  priority?: boolean;
};
```

| | mini | compact | medium | large |
|---|---|---|---|---|
| раскладка | горизонтальная строка | вертикальная | вертикальная | герой, ≥900px — split |
| медиа | 64×64, 1:1 | 16:9 | 16:9 | 3:2, ниже 640px — 16:9 |
| радиус | 18 | 18 | 22 | 28 |
| бейдж | нет, категория текстом | поверх медиа | поверх медиа | поверх медиа |
| заголовок | 14px, 2 строки | 16px, 3 строки | 20px, 3 строки | 26px, 3 строки |
| описание | нет | нет | 2 строки | 3 строки |
| мета | `źródło · czas` | `źródło · data` | `źródło · data` | `źródło · autor · data` |

Для `large` текст лежит поверх изображения, и читаемость обеспечивается **стопкой `drop-shadow()` разного радиуса на самом тексте** — приём из разобранного референса. Он лучше плоской градиентной шторки: тень следует форме букв, а не прямоугольнику, поэтому изображение остаётся видно. На узких экранах текст всё равно уходит под изображение.

**Пустое изображение**: `image_url` — обязательная строка, часто пустая. Проверять `article.image_url?.trim()` и **никогда не передавать пустой `src` в `next/image`** — это падение в рантайме. Подстановка занимает тот же бокс с тем же соотношением сторон, чтобы сетка не прыгала, и показывает тип материала через существующий `materialTypeLabel()`.

**Дата**: переиспользуем `formatDateTimePl()` из `lib/utils.ts`. Важная деталь: `<time dateTime="undated">` — невалидный HTML и обман для скринридера, поэтому `<time>` рендерится только при настоящем ISO, иначе обычный `<span>`.

**`Button`** — варианты `primary | secondary | quiet | ghost | danger`, размеры 32/40/48, формы `rounded | pill | icon`, `pressed` → `aria-pressed`, `loading` → `aria-busy` с сохранением ширины. Наличие `href` переключает на `next/link` — полиморфный проп `as` не нужен. У мелких и иконочных кнопок псевдоэлемент расширяет зону нажатия до 44px без изменения вида.

**`Dropdown`** — одна реализация вместо трёх нынешних. Роли `menu | single | multi`, полная клавиатура (стрелки с заворотом, Home/End, посимвольный поиск, Enter/Space), **Escape закрывает и возвращает фокус на триггер**, закрытие по `pointerdown` снаружи, `multi` не закрывается на выбор. `transform-origin` привязан к триггеру. Сейчас ни одна из трёх реализаций не имеет полного набора: у `mvp-sources-menu` нет ни Escape, ни клика снаружи.

**`NavMenu`** — полупрозрачная липкая шапка, `aria-current="page"` плюс подчёркивание (цвет не единственный сигнал), нижняя кромка появляется только после прокрутки через 1px-сентинел с IntersectionObserver, без слушателя скролла. Ниже 768px — раскрывающаяся панель.

**`SiteFooter`** — каждая колонка это свой `<nav aria-label>` со списком; нынешний футер внутри `PortalHome.tsx` использует один непомеченный `<nav>` из голых `<a>`. Текст дисклеймера переносим дословно — это редакционная политика, а не оформление.

## Сплошная система движения

Требование «морфинг после каждого действия везде» выполняется **системой**, а не анимацией, дописанной к каждому компоненту по отдельности. Разница принципиальная: ad-hoc анимации расходятся по таймингам, конфликтуют и в сумме дают ощущение неряшливости, а не жизни. Поэтому вводится правило: **ни один компонент не меняет визуальное состояние в обход примитивов движения.**

Что делает движение «живым», а не утомительным — три дисциплины, которые держим по всей системе:

1. **Быстро.** Служебные переходы 0.16–0.30s. Перетекание никогда не задерживает результат: данные появляются сразу, движется только их подача.
2. **Прерываемо.** Каждая анимация на пружине и стартует с текущего экранного значения. Пользователь в любой момент может передумать, и интерфейс не заставляет досматривать.
3. **Никогда не блокирует ввод.** Нет состояния «подожди, идёт анимация».

### Один живой элемент (уточнение владельца 24.09)

Правило для всей системы: **ничто не появляется рядом — всё вырастает из того, что его вызвало.** Триггер дропдауна разворачивается в панель (панель стартует из бокса кнопки — её ширины, высоты и радиуса — и растёт до своего размера; закрытие сворачивает её обратно в кнопку). Карточка разворачивается в предпросмотр, предпросмотр — в полный экран, не сбрасываясь. Кнопка, открывающая нижний лист, — точка, из которой лист вырастает. Активный индикатор переезжает, а не гаснет и зажигается. Скелет перетекает в контент. Следствие для реализации: у каждого «открывателя» и того, что он открывает, общая геометрия старта — либо через `layoutId`, либо через FLIP (замер бокса триггера → `initial` панели → анимация к `auto`). Появление «из ниоткуда» (чистое `opacity` + `scale` от центра) допустимо только для затемнения и уведомлений.

Набор маленький — это и есть залог связности:

### Область применения

Публичные страницы, портал и дашборд (`/editor`, `/editor/sources`, `/editor/political`, `/konto`) используют один и тот же набор. Поэлементная спецификация — ниже, отдельным разделом.

### Бюджет производительности

Это та часть, без которой «анимируем всё» превращается в тормоза. `layout` заставляет измерять элемент, и на сетке из 200 карточек наивное применение даёт сотни принудительных перерасчётов на каждое действие.

- `layout="position"` там, где меняется только позиция, — существенно дешевле полного `layout`.
- `LayoutGroup` вокруг каждой коллекции, чтобы несвязанные списки не измерялись вместе.
- Никогда не совмещать `layout` и анимацию появления на одном элементе.
- Каскады ограничены десятью позициями, `once: true`, `IntersectionObserver` — не подписка на скролл.
- Длинные ленты: при замере деградации — виртуализация либо ограничение `layout` видимой частью.
- Анимируем только `transform` и `opacity`; `will-change` оставляем framer-motion.

### Пружины

**`kit/motion/springs.ts`** — именованные пружины вместо фиксированных длительностей: пружина прерываема и стартует с текущего экранного значения. Таблица ниже — **единственный** источник имён; в коде и в этом документе других имён пружин нет.

Пружины задаём **только** парой `bounce` + `duration`, никогда через `stiffness/damping/mass`: последние перестают что-либо значить, когда одна и та же анимация проезжает путь от 184px до 1200px, а морфинг портала делает ровно это. Добавляем `restDelta: 0.5, restSpeed: 2` — при умолчаниях (0.01) пружина живёт ещё 10–20 невидимых кадров после визуальной остановки.

| Движение | bounce | длительность |
|---|---|---|
| наведение, левитация, свечение | **0** | 0.30 |
| нажатие | **0** | 0.16 |
| морфинг портала, открытие | **0.12** | 0.42 |
| морфинг портала, закрытие | **0** | 0.34 |
| содержимое внутри развернувшегося оверлея | **0.22** | 0.40, каскадом |
| появление лент и сеток | **0** | 0.30 |
| возврат после перетаскивания | **0.25** | 0.38 |

Три правила, которые стоит держать в голове:

1. **Overshoot — это утверждение, что у объекта была инерция.** Её не было при наведении, нажатии, открытии дропдауна и простом появлении — там bounce читается как дефект.
2. **Закрытие никогда не пружинит.** Возврат домой это оседание, а не бросок; на выходе overshoot заставляет карточку проскочить мимо своего места и дёрнуться назад — выглядит сломанным.
3. **Bounce на самом контейнере морфинга ограничен 0.15.** Пружина с отскоком перелетает одновременно позицию и проецируемый размер: при 0.12 поверхность на пике вылезает за окно примерно на 4% по каждой оси. Спасает `overflow: hidden` на поверхности (он и так нужен для скругления). Если ощущается плоско — добавляем отскок **содержимому** (0.22), а не контейнеру: глаз читает всю сцену как более живую, и ничего не выходит за экран.

В `providers.tsx` оборачиваем дерево в `<MotionConfig reducedMotion="user">`. Глобальный CSS-килсвитч `prefers-reduced-motion` в `globals.css` (23–25) действует только на CSS-анимации и **не останавливает** framer-motion, который пишет `style.transform` на каждом кадре — решать нужно в JS через `useReducedMotion()`. В сам килсвитч стоит добавить комментарий об этом, иначе следующий человек потеряет час.

**Портал.** `PortalProvider` хранит открытый материал и исходный элемент. Оверлей обязательно `createPortal` в `document.body`: `.material-strip` имеет `overflow-x: auto`, а `.material-box` — `overflow: hidden`, то есть карточка физически не может «вырасти» из своей ленты. Морфинг через портал работает, потому что framer-motion меряет координаты относительно окна. **Это проверяем самым первым, до того как что-либо на этом строить.**

Не используем `<dialog>.showModal()`, как сделаны четыре нынешних модалки: top layer приносит свой `::backdrop`, свою ловушку фокуса и в Safari собственный переход закрытия, который гонится с нашим морфингом. Отказ перемежающийся и плохо диагностируется.

`<AnimatePresence>` монтируется **постоянно**, условным делается только его ребёнок — обратное это причина номер один для «анимация выхода не проигрывается». Режим оставляем `sync`: `mode="wait"` ломает общую раскладку, которой нужно, чтобы оба элемента прожили один общий кадр.

Детали, без которых эффект выглядит сломанным:

- **Скругление** — инлайново и числом, на том же элементе, что несёт `layoutId`. Морфинг это проекция `translate + scale`, а не анимация `width/height`, поэтому радиус из CSS растягивается в эллипс: framer-motion корректирует только те радиусы, которыми владеет сам. Значит, из `globals.css` радиусы карточки и медиа-бокса **переезжают в компонент**.
- **Изображение** получает собственный вложенный `layoutId` на обёртке. Иначе `<img>` с `fill` просто масштабируется вместе с родителем 6.5× по горизонтали и 8× по вертикали и весь полёт выглядит резиновым. Строка `src` должна совпадать байт в байт, чтобы браузер взял картинку из памяти без повторной загрузки.
- **`layoutId` выдаётся только активной карточке.** Всегда включённый идентификатор означает проход измерения по 250 элементам (столько набирается на главной) при каждом открытии и закрытии. Карточка получает идентификатор и оверлей монтируется в **одном** React-коммите, поэтому измеряются ровно два элемента. Отсюда следствие: `setActive` нельзя заворачивать в `startTransition`, иначе они разъедутся по коммитам и морфинг стартует из неверной точки.
- **Блокировка скролла с компенсацией полосы прокрутки** и через `useLayoutEffect`. Без компенсации страница станет на ~15px уже, и все измеренные прямоугольники карточек сдвинутся между замером и первым кадром — морфинг поедет по горизонтали. Заодно на время оверлея гасим `scroll-behavior: smooth` из `globals.css:11`.
- **Фокус**: `inert` на `#main-content` и шапке вместо рукописной ловушки — это ещё и блокирует поиск по странице и указатель. Начальный фокус ставится **после** завершения морфинга, возврат — в `onExitComplete`, когда карточка уже на месте. Везде `focus({ preventScroll: true })`, иначе плавная прокрутка из `globals.css:11` уведёт кадр.
- **Возврат, три случая.** Карточка на экране — обычный морфинг. Карточка смонтирована, но уехала из области просмотра — мгновенный `scrollIntoView({ behavior: 'instant' })` в том же синхронном такте. Карточка размонтирована (сменились фильтры `Baza`, перезапросилась страница ленты) — морфить не к чему, закрываем уменьшением к центру сохранённого при открытии прямоугольника.

**Адрес.** Источник истины — состояние React; адрес лишь отражает его.

- `window.history.pushState`, **никогда `router.push`**: настоящая навигация App Router подтянет RSC-пейлоад сегмента `/material/[id]` и **размонтирует `PortalHome` вместе со всеми карточками** — партнёр морфинга исчезнет на лету. `scroll: false` не спасает, проблема в размонтировании. Это стоит отдельным комментарием в коде.
- **Адрес обязан сохранять строку запроса.** `PortalHome` читает `q` из `useSearchParams` и передаёт в `Baza`, а тот сбрасывает своё поле поиска по изменению `initialQuery`. Уронив `?q=`, мы молча стираем поиск пользователя и перезапрашиваем всю ленту прямо при открытом оверлее. Поэтому `pushState` всегда клеит `window.location.search`.
- Все пути закрытия идут через `history.back()`, поэтому крестик и кнопка «Назад» — буквально один код, а стек истории не растёт. Переход «материал → связанный материал» внутри оверлея использует `replaceState`, чтобы один «Назад» возвращал на главную, а не отматывал цепочку.
- Прямой заход, обновление и присланная ссылка попадают на существующую серверную страницу. `generateMetadata` выполняется только на сервере, поэтому **на OG-превью и шаринг это не влияет вообще** — краулер всегда запрашивает адрес заново. Внутри сессии просто правим `document.title` вручную и возвращаем при закрытии.
- Плюс к этому: страница `/material/[id]` и оверлей должны рендерить **один и тот же** компонент `MaterialSurface` с пропом `mode: 'page' | 'overlay'`, который управляет только наличием `layoutId`, видом кнопки закрытия, блокировкой скролла и a11y-обвязкой. Так они никогда не разъедутся.

**Закрытие перетаскиванием**: `drag="y"`, решение по **знаку скорости**, а не по достигнутой позиции; для медленного отпускания — проекция инерции `current + (v/1000)·d/(1−d)` при `d ≈ 0.99`. Прозрачность фона, масштаб и радиус меняются **во время** жеста через `useTransform` — на композиторе, без единого React-рендера; поверхность видимо «отрывается», пока её тянут. Жест стартует только когда внутренний скроллер в нуле (`dragListener={false}` + `dragControls`), иначе попытка прокрутить вверх будет закрывать оверлей. Честная оговорка: настоящая передача скорости возможна на пути возврата (пружина по `MotionValue` принимает начальную скорость), а выход — это layout-анимация с единым прогрессом, в которую скорость по осям не вложить; компенсируем тем, что проекция и так стартует с текущего экранного значения, а длительность делаем зависимой от скорости отпускания.

**Появление лент** — `whileInView` с `IntersectionObserver` и `once: true`, задержка `min(index, 10) × 0.035`, смещение 8px. Именно так, а не `staggerChildren`: на контейнере с 200 карточками (куда `Baza` доезжает быстро) это семисекундный каскад, всё это время держащий каждый элемент в анимируемом состоянии. И ни в коем случае не `useScroll` на каждую карточку — это подписка сотен элементов на скролл и гарантированные рывки в горизонтальных лентах. Пока оверлей открыт, каскады за ним приостанавливаем: сетка всё равно под затемнением, а кадры она отнимает.

### Три ступени взаимодействия с карточкой

Карточка отвечает не одним состоянием, а лестницей из трёх, где каждая следующая требует больше намерения. Это и даёт ощущение, что интерфейс отзывается постепенно, а не переключается.

| Ступень | Чем вызывается | Что происходит |
|---|---|---|
| **A — подсветка** | курсор вошёл, **немедленно** | `scale 1→1.03`, янтарное свечение, подъём, кромка к акценту |
| **B — предпросмотр** | курсор задержался **400ms** | морфинг к увеличенной карточке: `scale` до 1.10–1.14 по размеру, раскрывается описание, мета целиком, действия |
| **C — полный экран** | клик | морфинг в оверлей портала |

**Отскок на ступенях A и B.** Владелец просит bounce на обеих. Оговорю один раз и сделаю как просят: сам по себе отскок означает «у объекта была инерция», а у наведения инерции нет — поэтому значение берём **маленькое и быстрое**, `bounce 0.18 / 0.26s` на ступени A и `bounce 0.22 / 0.38s` на ступени B. При больших значениях проводка мыши над сеткой заставит десяток карточек трястись одновременно, и живость превратится в дрожь. Точные величины подбираем на витрине, где обе ступени стоят рядом с регулятором.

**Лестница работает в обе стороны.** Уход курсора со ступени B возвращает на A, а не сразу в покой — обратный путь повторяет прямой. Уход с A — в покой. Каждый переход прерываем: если курсор вернулся на середине сворачивания, движение разворачивается с текущей точки.

**Клик на любой ступени продолжает движение.** Это ключ к непрерывности: морфинг в полный экран стартует с того размера, который карточка имеет **сейчас** — подсвеченного или уже развернутого в предпросмотр, — а не сбрасывает её в покой. Framer Motion делает это сам, если мы не сбрасываем состояние перед открытием; значит, не сбрасываем.

**Порог намерения на ступени B** — 400ms, и он отменяется мгновенно при уходе курсора. Без задержки проводка мыши через ленту устроит волну раскрытий. С клавиатуры ступень B наступает **сразу по фокусу**: табуляция уже является явным намерением, ждать нечего.

### Ступень B: как именно раскрывается предпросмотр

Предпросмотр показывает то, чего нет в покое: описание, источник целиком, дату, действия. Внутри развернувшейся карточки дополнительный блок проявляется каскадом: `opacity 0→1`, `y 6→0`, шаг `0.03s`. Сворачивание — без задержки, `collapse`; асимметрия намеренная: раскрытие требует намерения, сворачивание — нет.

**Слой выше, а не поток.** Уточнение владельца (23.09): развернутая карточка **никогда не влияет на сетку и не сдвигает содержимое страницы**. Поэтому предпросмотр всегда рендерится в слое поверх страницы — в той же `PortalLayer`, что и полноэкранный морфинг (клон над оригиналом, оригинал остаётся на месте как место-держатель), **и в сетке, и в ленте**. Никакого «в сетке — по месту»: любой дополнительный блок (описание, действия), добавленный в поток внутри карточки, меняет её высоту и толкает соседей — это ровно то, чего быть не должно. Увеличение делается `transform`, слой лежит выше всего, включая липкие панели. При уменьшенном движении предпросмотр появляется в том же слое затуханием, без масштаба.

**`transform-origin` зависит от места.** Крайняя левая карточка растёт вправо, крайняя правая — влево, верхний ряд — вниз. Иначе раскрытие уезжает за край экрана. Определяется один раз при наведении по `getBoundingClientRect()`.

**Главное техническое ограничение.** `.material-strip` имеет `overflow-x: auto; overflow-y: hidden` — развернувшаяся карточка будет **обрезана** лентой. Поднять `overflow-y` до `visible` нельзя: по спецификации при `overflow-x: auto` второе значение `visible` вычисляется в `auto`, и вертикальный рост всё равно обрежется. Поэтому раскрытие в лентах рендерится **в том же слое-портале, что и полноэкранный морфинг**: при подтверждении намерения снимается прямоугольник карточки, поверх позиционируется её развернутая копия, оригинал остаётся на месте как место-держатель. Инфраструктура уже есть — это та же `PortalLayer`, только без затемнения, без блокировки скролла и без изменения адреса. В обычной сетке (`Baza`), где обрезки нет, раскрытие идёт на месте, без портала.

**Ограничения по устройствам и доступности.** Только `@media (hover: hover) and (pointer: fine)` — на тач-устройствах раскрытия по наведению нет вообще, там его роль выполняет тап. Фокус с клавиатуры раскрывает **без задержки** — клавиатурная навигация уже является явным намерением. При уменьшенном движении раскрытие не масштабирует карточку: дополнительный блок просто проявляется по месту.

**Что не делаем:** не запускаем видео и не подгружаем данные по наведению. Раскрытие показывает то, что уже загружено.

### Раскрытие карточки по клику

Продолжение состояния наведения, а не новая анимация с нуля. Это и есть непрерывность, которую просил владелец.

1. **`pointerdown`** — `scale .97` немедленно, `press`. Отклик на нажатие, а не на отпускание.
2. **`pointerup`** — морфинг стартует **сразу**, без промежуточной паузы. Никаких «сначала приподнялась, потом полетела»: любая добавленная задержка ощущается как тормоз.
3. **Старт с текущего состояния.** Если карточка была развернута по наведению или ещё сжата от нажатия, морфинг начинается **с этого экранного значения**, а не с состояния покоя. Framer Motion делает это сам, потому что проекция стартует с презентационного значения — но только если мы не сбрасываем состояние перед открытием. Не сбрасываем.
4. **Направление подсказывает результат.** В первой трети морфинга тень углубляется быстрее размера, поэтому карточка читается как «поднялась и полетела вперёд», а не «растянулась».
5. **Затемнение** нарастает чуть быстрее морфинга (`scrim` 0.28 против `portalIn` 0.42), чтобы фон ушёл раньше, чем поверхность займёт экран — иначе в середине полёта видна каша из полуразвернутой карточки и ещё яркой сетки.
6. **Содержимое** оверлея входит каскадом уже **во время** морфинга, с задержкой 0.12s от старта, а не после его завершения. Ожидание окончания даёт ощущение двух отдельных этапов вместо одного движения.

Прерывание: клик по другой карточке, пока предыдущая ещё летит, перенацеливает анимацию, а не ставит её в очередь.

### Переходы между страницами

Честно о платформе: **App Router не умеет анимировать выход маршрута.** Старое дерево размонтируется до того, как отрисуется новое, поэтому `AnimatePresence` по маршруту без хаков с «замороженным роутером» не работает. Хак хрупкий и ломается на каждом обновлении Next — не берём.

Рабочая схема из трёх уровней, от самого важного к необязательному:

1. **Основной поток «карточка → материал» вообще не является навигацией.** Это морфинг портала с подменой адреса. Самый частый переход в продукте получается самым плавным — и именно поэтому архитектура портала выбрана такой.
2. **Для настоящих переходов** — `template.tsx`. В отличие от `layout.tsx`, он **перемонтируется на каждую навигацию**, что даёт анимацию входа бесплатно и без хаков: `opacity 0→1`, `y 8→0`, `fade`.

   Важная деталь стадийности: на этом этапе файл кладётся в `frontend-spin/app/ui-kit/template.tsx`, то есть **только на сегмент витрины**. Положить его в корень `app/` означало бы выдать анимацию входа всем живым страницам сразу — а это ровно то изменение живого поведения, которое отложено до утверждения вида, и оно сломало бы критерий проверки «живые страницы выглядят в точности как раньше». На этапе 2 файл просто переезжает в корень.
3. **Мгновенная обратная связь на клик по ссылке.** Раз выход анимировать нельзя, ощущение отклика даёт сама ссылка: нажатие сразу отзывается `press`, а активный пункт навигации переезжает `layoutId` **до** того, как новая страница отрисуется. Пользователь видит реакцию мгновенно, а не после загрузки сегмента.

Дополнительно, как прогрессивное улучшение: где браузер поддерживает View Transitions API, переход между разделами можно обернуть в `document.startViewTransition` — тогда появляется и кроссфейд выхода. Где не поддерживает — остаётся уровень 2. Делаем **после** утверждения основного вида, отдельной проверяемой правкой: в Next 14 это ручная интеграция, а не встроенная возможность.

Прокрутка при переходе: наверх мгновенно (`behavior: 'instant'`), потому что плавная прокрутка из `globals.css:11` в сочетании с анимацией входа даёт два независимых движения одновременно и читается как рассинхрон.

### Переходы между секциями

| Событие | Что происходит | Пружина |
|---|---|---|
| Переход к секции по якорю (поиск уводит к `Baza`) | прокрутка пружиной, а не `behavior: 'smooth'`: браузерная плавная прокрутка не прерывается и игнорирует встречные действия пользователя | `move` |
| Появление секции при прокрутке | заголовок и содержимое входят каскадом `0.04s`, один раз | `ui` |
| Переключение вкладок внутри секции | индикатор переезжает `layoutId`; панели меняются кроссфейдом, контейнер **морфит высоту** под новое содержимое, чтобы низ страницы не прыгал | `move` + `fade` |
| Раскрытие `<details>`-фильтров | высота разворачивается `expand`, содержимое проявляется с задержкой 0.06s | `expand` |
| Сворачивание | высота `collapse`, содержимое гаснет первым | `collapse` |
| Липкий заголовок секции | уплотняется по сентинелу `IntersectionObserver` | `fade` |

При уменьшенном движении: прокрутка мгновенная, высота меняется без анимации, остаются только кроссфейды.

### Списки, сетки и ленты

| Событие | Что происходит | Пружина |
|---|---|---|
| Смена фильтра или категории | уцелевшие карточки **едут** на новые места, ушедшие гаснут, пришедшие проявляются — три группы одновременно, а не последовательно | `move` + `collapse` + `ui` |
| Ввод в поиск | то же самое, с подавлением дребезга; уже показанные совпадения не перерисовываются, а переезжают | `move` |
| Догрузка ленты | новые карточки входят каскадом, **индексация внутри страницы**, иначе третья страница начнётся с максимальной задержки | `ui` |
| Сортировка | чистое переупорядочивание `layout="position"` | `move` |
| Пустой результат | сетка сжимается, сообщение проявляется — не мгновенная подмена | `collapse` + `fade` |
| Горизонтальная лента | прокрутка с инерцией и мягким примагничиванием; стрелки прокручивают пружиной, а не рывком | `move` |
| Счётчик результатов | число перетекает между значениями, а не перескакивает | `move` |

### Загрузка

Скелет — не отдельный экран, а то же самое место: блоки скелета стоят в тех же боксах, что будущий контент, и при готовности данных **перетекают** в него (`fade`, 0.25s) без изменения раскладки. Никакого мигания пустотой и никакого прыжка высоты. Пульсация скелета — мягкая, период не короче 1.6s; при уменьшенном движении пульсация выключается, остаётся статичная плашка.

### Перетаскивание полос новостей

Пользователь меняет порядок полос на странице перетаскиванием. Реализуется на `Reorder.Group` / `Reorder.Item` из framer-motion — новой зависимости не нужно, и раскладка соседей анимируется встроенно.

**Захват только за ручку.** Внутри полосы горизонтальная прокрутка, поэтому тащить за саму полосу нельзя — жест конфликтует с прокруткой и отбирает её. Слева у заголовка полосы появляется ручка (иконка `grip`), видимая при наведении на полосу и всегда видимая при фокусе с клавиатуры. На тач-устройствах захват — долгое нажатие 250ms, иначе пропадёт вертикальная прокрутка страницы.

| Событие | Что происходит | Пружина |
|---|---|---|
| Наведение на ручку | курсор `grab`, ручка проявляется, свечение | `ui` |
| Захват | полоса поднимается: `scale 1.02`, тень `e-3`, свечение усилено, остальные слегка приглушаются `opacity .75` | `sheet` |
| Перетаскивание | полоса 1:1 за курсором по вертикали; соседи расступаются `layout`, освобождая место | `move` |
| У края экрана | автопрокрутка страницы со скоростью, растущей по мере приближения к краю | — |
| Отпускание | полоса опускается на место с передачей скорости; тень и приглушение возвращаются | `settle` |
| Escape во время перетаскивания | отмена: полоса возвращается на исходное место | `collapse` |

**Клавиатура обязательна.** Чистый указательный drag&drop недоступен. Ручка получает фокус; `Space` — взять, `↑`/`↓` — переместить на позицию, `Space` — положить, `Escape` — отменить. Каждое перемещение объявляется через `aria-live`: «Polska — pozycja 2 z 6».

**Сохранение порядка.** На этом этапе — в `localStorage`, без обращения к API: контракты бэкенда не трогаем, а профильного поля под порядок полос сейчас нет. Честно отражаем это в интерфейсе: порядок сохраняется на устройстве, не на аккаунте. Синхронизация с профилем — отдельная задача, требующая изменения бэкенда.

**Уменьшенное движение**: подъём и масштаб отключаются, перестановка происходит мгновенно, но соседи всё равно занимают новые места — иначе непонятно, что произошло.

### Селекторы, флажки и переключатели

Общий принцип: **состояние не переключается, а перетекает**. Каждый контрол имеет полный набор состояний — покой, наведение, фокус, нажатие, включено, неопределённое, заблокировано, ошибка — и каждый переход между ними анимирован.

**О «переливе».** Делаем его **однократной вспышкой на смену состояния**, а не бесконечным мерцанием: диагональный блик проходит по контролу один раз за 0.4s в момент включения. Постоянно переливающиеся флажки на форме с двумя десятками фильтров превращаются в рябь, никогда не дают глазу точку покоя и первыми раздражают при долгой работе — а `Baza` это именно долгая работа. Токен `--sc-sheen`, при уменьшенном движении блик не проигрывается вовсе.

| Контрол | Включение | Выключение | Прочие состояния |
|---|---|---|---|
| **Флажок** | рамка → заливка акцентом сквозь диагональный блик; галочка **прорисовывается** штрихом (`stroke-dashoffset` 0.2s), а не появляется целиком; коробочка `scale 1→.92→1` | галочка стирается обратным штрихом, заливка гаснет | неопределённое — черта растёт от центра к краям; ошибка — рамка перетекает в `--sc-negative`, лёгкое встряхивание 2px один раз |
| **Радио** | точка `scale 0→1` пружиной из центра, кольцо подкрашивается | точка ужимается в ноль | в группе точка «переезжает» между вариантами общим `layoutId`, а не гаснет и зажигается |
| **Переключатель** | бегунок едет пружиной, дорожка перетекает по цвету; бегунок **слегка растягивается** по ходу движения и собирается в конце — подсказка направления | зеркально | заблокированный — `opacity .4`, движение остаётся, чтобы состояние читалось |
| **Сегментированный** | индикатор переезжает `layoutId`, подписи перекрашиваются | — | нажатие — весь контрол `scale .98` |
| **Пилюля-фильтр** | фон и кромка перетекают, счётчик рядом перетекает числом | — | активная получает слабое свечение |
| **Селект** | шеврон поворачивается на 180°, панель растёт из триггера | шеврон обратно | выбранное значение в закрытом состоянии сменяется кроссфейдом |
| **Поле поиска** | кольцо фокуса и кромка перетекают, иконка перекрашивается в акцент; кнопка очистки появляется `scale .8→1` | — | при вводе — счётчик результатов перетекает числом, без мигания |

Общее для всех: зона нажатия не меньше 44px независимо от нарисованного размера; состояние никогда не передаётся одним лишь цветом — всегда есть форма (галочка, точка, положение бегунка) или текст; фокус даёт то же кольцо, что у кнопок.

### Формы и поля ввода

Фокус поля — кольцо и рамка перетекают (`fade`). Ошибка валидации **не появляется мгновенно**: сообщение разворачивается по высоте с `expand`, поле подсвечивается цветом; поля ниже съезжают `layout`, а не прыгают. Исчезновение ошибки — `collapse`. Состояние сохранения (`Zapisano`) проявляется и уходит затуханием, без сдвига соседей.

### Смена темы

Самый заметный «скачок», если его не обработать. Переключение день/ночь идёт плавным переходом цвета: на `<html>` на время переключения вешается класс с `transition` на `background-color` и `color` (~0.25s), который снимается по завершении. Переход именно на корне, а не на каждом элементе — иначе это сотни одновременных переходов. При уменьшенном движении и при `prefers-contrast: more` переход мгновенный: плавное изменение яркости на весь экран — ровно то, чего просят избегать.

### Модалки дашборда и редакции

Те же правила, что у дропдауна и портала: рост из точки вызова, симметричный выход, каскад содержимого, затемнение параллельно. Добавление и удаление строк в редакторе нитки (`MojaNitkaEditor`) и переупорядочивание материалов — `MorphList` с `layout`; перетаскивание элемента нитки использует ту же физику, что закрытие портала: 1:1 за курсором, проекция инерции, решение по знаку скорости.

## Мобильные раскладки

На телефоне нет наведения, поэтому лестница «подсветка → предпросмотр → полный экран» переводится на другие сигналы: **положение на экране** заменяет наведение, **касание** заменяет задержку курсора. Это не упрощённая версия десктопа, а отдельная механика с тем же характером движения.

### Основания

- **Точки перелома**: `≤ 480` телефон, `481–900` планшет и узкое окно, `> 900` десктоп. Внутри телефонного диапазона макет проверяется на 375, 390 и 430 — этим покрыты компактные, стандартные и крупные экраны.
- **Безопасные зоны**: все липкие элементы и нижние листы учитывают `env(safe-area-inset-top/bottom)`; ничего важного не лежит под вырезом и под индикатором «домой».
- **Зона большого пальца**: главные действия — открыть, закрыть, применить фильтр — в нижней половине экрана. Верх экрана — для чтения, не для нажатий.
- **Касания не меньше 44×44**, между соседними целями не меньше 8px.
- **Одна колонка** до 480, две — на планшете. Карточка `medium` на телефоне занимает всю ширину; `large` становится вертикальной с текстом под изображением; `compact` остаётся горизонтальной строкой; `mini` без изменений.
- **Шапка** уплотняется при прокрутке вниз (высота 64 → 48, поиск сворачивается в иконку) и разворачивается при прокрутке вверх — по знаку направления, не по позиции. Навигация — в нижнем листе по иконке `menu`, который морфится в `close`.
- **Дропдауны и фильтры** на телефоне — **нижние листы**, а не всплывающие панели: панель шириной 220px под пальцем неудобна, лист даёт крупные цели и знакомый жест закрытия. Лист использует ту же физику, что закрытие портала: 1:1 за пальцем, проекция инерции, решение по знаку скорости, резиновая граница сверху.

### Фокус при прокрутке — замена наведению

На экране определяется **фокальная полоса** — 35–65% высоты области просмотра. Карточка, чей центр ближе всего к центру этой полосы, получает ступень **A** автоматически: `scale 1.03`, свечение, кромка. Одновременно «в фокусе» ровно одна карточка; при прокрутке фокус **перетекает** с одной на другую — уходящая опускается, приходящая поднимается, обе на `ui`.

Как это сделано, чтобы не тормозить: `IntersectionObserver` с `rootMargin`, сжимающим корень до фокальной полосы, — **не** слушатель прокрутки. Наблюдаются только смонтированные видимые карточки. При быстрой прокрутке фокус не перескакивает через каждую карточку, а догоняет остановку: смена фокуса подавляется, пока скорость выше порога, и срабатывает на замедлении.

Ступени на телефоне:

| Ступень | Чем вызывается | Что происходит |
|---|---|---|
| **A** | карточка вошла в фокальную полосу | подсветка, как на десктопе |
| **B** | касание карточки в фокусе | предпросмотр **разворачивается по месту**: высота растёт `expand`, соседи ниже съезжают `layout`, проявляется описание и кнопка «Otwórz» |
| **C** | касание развернутой карточки или «Otwórz» | морфинг в полный экран |

Касание карточки **не в фокусе** делает два движения одним: прокручивает её в фокальную полосу и разворачивает в B. Свайп вверх по развернутой карточке или касание вне её — сворачивание.

Ступень B добавляет одно касание на пути к материалу — это осознанная плата за лестницу, которую просит владелец. Она проверяется на витрине вживую; если окажется лишней, касание ведёт сразу в C, а B остаётся доступной долгим нажатием.

Уменьшенное движение: фокус не масштабирует карточку, а только подкрашивает кромку и свечение; разворачивание B происходит без анимации высоты.

### Разворачивание секций при прокрутке

Страница загружается **сложенной**: каждая секция ниже первого экрана показана заголовком и одним рядом. Когда заголовок секции пересекает фокальную полосу, секция **разворачивается**: высота растёт `expand`, содержимое входит каскадом. Один раз — обратно она не складывается. Так первый экран лёгкий, а прокрутка ощущается как последовательное раскрытие, а не как чтение бесконечной простыни.

Заголовок секции липнет к уплотнённой шапке с полупрозрачной подложкой и уступает место следующему заголовку, выталкиваясь вверх, — переход между секциями виден без разделителей.

Горизонтальные ленты превращаются в **карусели с примагничиванием** (`scroll-snap-type: x mandatory`) и выглядыванием следующей карточки на 16% ширины — так видно, что можно листать. Карточка, примагниченная к центру, получает ступень A; касание — B: слайд растёт по высоте, и **высота всей ленты морфит** под него, чтобы страница ниже сдвинулась плавно, а не прыгнула.

### Экраны

Телефонная раскладка каждого маршрута описана постранично в разделе «Дизайн страниц и панелей» (колонка «Телефон» и абзацы про телефон). Здесь — только то, что относится к витрине: все разделы в одну колонку; стенд движения включает **эмуляцию фокальной полосы** с подсвеченными границами; обязательно проверяется на 375 в эмуляции тач-устройства.

### Что проверяется только на телефоне

Долгое нажатие для перетаскивания не конфликтует с контекстным меню системы (гасим через `touch-action` и `-webkit-touch-callout`). Горизонтальная карусель не перехватывает вертикальную прокрутку — `touch-action: pan-x` только на самой ленте. Нижний лист не тянет за собой страницу — `overscroll-behavior: contain`. Фокус при прокрутке не срабатывает во время инерционной прокрутки, а только на замедлении.

## Каталог иконок

**Система.** Сетка 24×24, штрих 1.5px, скруглённые концы и соединения, `currentColor`, без заливок. Размеры 16 / 20 / 24 — штрих при этом **не масштабируется пропорционально**, а задаётся отдельно (16px → 1.25px, 20px → 1.5px, 24px → 1.5px), иначе мелкие иконки выглядят жирнее крупных рядом с ними.

Причина не только в весе: правило проекта требует, чтобы декоративная графика была собственной, а набор здесь нужен небольшой и предсказуемый. ## Разбор референса NovusIgnis / Omniforum

Смотрел исходники сайта (`novusignis.org/style.css`, 2765 строк, и `script.js`, 973 строки) через GitHub API — открыть сайт в браузере не дали настройки безопасности, но исходный код оказался информативнее рендера.

**Что там на самом деле происходит.** Палитра — угольно-чёрная с огненными акцентами: `--ni-ember #FF3300`, `--ni-flame #FF6B00`, `--ni-amber #FFB800`, плюс холодный `--ni-cyan #00FFEE` для контрапункта. Ощущение «перетекания» даёт не CSS (там всего 29 переходов и 5 наборов ключевых кадров на 2765 строк), а `script.js`: прокрутка переводится в прогресс `p` от 0 до 1, и этим прогрессом управляются кроссфейды сцен-изображений, затухание и уменьшение героя, канвасный эффект искр и закреплённые секции. Есть аккуратная функция `fadeWin(p, start, peakStart, peakEnd, end)` — окно появления и ухода элемента по прогрессу.

**Главный вывод: это другой жанр.** NovusIgnis — манифест-лендинг: несколько длинных кинематографичных сцен и тяжёлые изображения. spin.clinic — плотный архив с сотнями карточек, фильтрами, бесконечной лентой и редакционной панелью. Кинематографичная прокрутка со сценами там была бы вредна: она мешает сканировать, бьёт по производительности на сотнях карточек и противоречит серьёзной редакционной интонации проекта. Поэтому заимствуем **приёмы, а не жанр**.

### Что берём

1. **Кривая `cubic-bezier(0.16, 1, 0.3, 1)`.** Резкий старт с долгим мягким доводом — по характеру это ровно то же, что критически задемпфированная пружина. Берём как токен `--sc-ease-standard` для тех переходов, где пружина избыточна: цвет, прозрачность, кромка.
2. **Подтверждение механики наведения.** У них карточка ведёт себя так: `transform: translateY(-4px)`, кромка подкрашивается в акцент, тень углубляется, и **слой `::before` со свечением проявляется по прозрачности**. Это буквально то, что уже описано в нашем разделе про наведение — значит, направление угадано верно. Забираем оттуда две конкретные детали: **подкрашивание кромки** в сторону акцента (дёшево и сильно добавляет к ощущению «подсвечено сзади») и величину подъёма `−4px` для крупных карточек.
3. **Многослойный `drop-shadow()` для читаемости текста поверх изображения.** Они складывают несколько чёрных теней разного радиуса вместо одной плоской подложки. Для нашей большой карточки с заголовком поверх фотографии это лучше градиентной шторки: тень следует форме букв, а не прямоугольнику, и изображение остаётся видно. Берём именно для этого случая.
4. **Тёплую часть палитры.** Наш янтарь `#E0A452` довольно приглушённый, редакционный. Для ночной темы имеет смысл сдвинуть свечение на пол-шага теплее, ближе к их `#FFB800`, — но **только свечение**, не акцент: синий остаётся рабочим цветом.
5. **Идею окна по прогрессу (`fadeWin`).** Полезна в строго ограниченном виде: уплотнение шапки на коротком отрезке прокрутки, мягкое проявление иллюстрации в шапке главной. Не для сетки карточек.

### Что сознательно не берём

- **Кинематографичные закреплённые сцены и перехват прокрутки.** Для архива, где люди сканируют и ищут, это прямой вред.
- **Слушатель прокрутки на `requestAnimationFrame`.** У них он один на страницу и это оправдано. У нас сотни карточек, поэтому остаёмся на `IntersectionObserver` — решение уже зафиксировано в бюджете производительности.
- **Бесконечную пульсацию свечения** (`logoPulse 3s ease-in-out infinite`). На логотипе лендинга уместно; в новостном интерфейсе это шум, к тому же медленные зацикленные колебания — то, чего рекомендуют избегать в интерфейсах, которыми пользуются подолгу.
- **`transition: all`.** Встречается у них несколько раз. Анимирует в том числе свойства раскладки и мешает композитору — у нас перечисляем свойства поимённо.
- **Анимацию самого `filter`.** Свечение у них живёт на `filter` элемента; анимировать `filter` дорого. Мы оставляем анимацию на псевдоэлементе через `opacity` и `transform`, а `drop-shadow` используем статически — только для текста поверх изображений.
- **Отсутствие поддержки уменьшенного движения.** Проверил отдельно: `prefers-reduced-motion` не встречается ни в `style.css`, ни в `script.js` — ни разу. При их насыщенности прокруткой это заметный пробел. Наследовать его не будем.

## Витрина `/ui-kit`

Тонкая серверная страница по образцу `app/box-materialu/page.tsx`, с `robots: { index: false, follow: false }`. Ссылок на неё из живой навигации на этом этапе не ставим.

Разделы: баннер о демонстрационном характере → управление (тема, принудительные режимы доступности) → токены → **типографика** → карточка во всех четырёх размерах × шести состояниях (обычное · без миниатюры · без даты · дата не установлена · очень длинный заголовок · очень длинное имя источника) → кнопки → дропдауны → навигация → футер.

**Типографический раздел** показывает каждую ступень шкалы на реальном польском тексте с диакритикой, с подписью фактического кегля, интерлиньяжа, трекинга и веса. Обе темы выводятся **рядом, в одном поле зрения** — иначе оптическую компенсацию веса невозможно оценить: на глаз по памяти разницу между 600 и 700 на разных фонах никто не поймает. Отдельная строка — длинные польские составные слова, чтобы сразу увидеть, как Montserrat переносит их в узкой карточке.

Отдельно — **стенд движения**, по которому вид и принимается. На нём каждая строка поэлементной спецификации выше воспроизводится по кнопке, а не ловится случайно:

- свечение и левитация на всех типах элементов рядом, в обеих темах;
- стенд пружин: одна и та же плашка, приводимая каждой из пружин, для сравнения характера;
- **проверка прерываемости**: кнопка, которая перебивает анимацию на середине встречным действием — движение обязано продолжиться с текущей точки;
- живой список с кнопками «добавить», «удалить», «перемешать», «отфильтровать» — здесь видно, как уцелевшие элементы едут, а не перерисовываются;
- переключение табов с переезжающим индикатором;
- перетекающий счётчик;
- скелет → контент по кнопке;
- **каталог иконок** целиком: каждая в трёх размерах, со своей анимацией, в обеих темах;
- **каждый контрол во всех состояниях** — покой, наведение, фокус, нажатие, включено, неопределённое, заблокировано, ошибка — сеткой, чтобы правка адресовалась к конкретной ячейке;
- перетаскивание полос: мышью, пальцем и с клавиатуры, с включённым объявлением позиции;
- раскрытие по наведению: одна и та же карточка в обычной сетке и внутри ленты с `overflow-x: auto` — рядом, чтобы видеть, что обрезки нет;
- **непрерывность жеста**: клик по уже развернутой наведением карточке — морфинг обязан продолжиться с текущего размера, а не сброситься;
- портал: открытие, переход к связанному материалу, перетаскивание, и все три случая возврата, включая «карточка размонтирована»;
- переходы между разделами витрины и вкладками внутри раздела: переезд индикатора, морфинг высоты панели;
- **мобильный стенд**: фокальная полоса с подсвеченными границами, чтобы видеть, какая карточка в фокусе и как фокус перетекает; сложенная секция, разворачивающаяся при прокрутке; карусель с примагничиванием; нижний лист с перетаскиванием;
- поле с ошибкой валидации: разворачивание сообщения и съезд соседей.

**Переключатель темы на витрине меняет только `dataset.theme`** и восстанавливает исходное значение при размонтировании. Он не пишет в `localStorage` и не делает `PATCH /api/account/profile/` — иначе просмотр витрины молча перезапишет реальную настройку владельца.

**Фикстуры** по принятой в проекте конвенции (см. шапку `lib/powiekszonyBoxDemo.ts`): комментарий о полной вымышленности, домен `przyklad.invalid`, отрицательные `id`, чтобы исключить совпадение с настоящим материалом. Названия источников заведомо выдуманные (`Dziennik Przykładowy`, `Serwis Testowy`). **Заголовки описывают раскладку, а не события** — «Bardzo długi tytuł testowy sprawdzający zawijanie…», не «Rząd przyjął projekt ustawy»: правило `docs/FRONTEND_MVP_DIRECTION.md` запрещает вымышленные новости, и правдоподобный заголовок нарушает его даже в фикстуре. Изображения — инлайновые `data:image/svg+xml` градиенты со словом DEMO, без бинарных файлов в репозитории (работает, потому что `images: { unoptimized: true }` уже стоит).

4а. **Три ступени на десктопе**: подсветка мгновенно, предпросмотр после задержки, клик на любой ступени продолжает движение с текущего размера; уход курсора с предпросмотра возвращает через подсветку, а не сразу в покой.
4б. **Телефон** в эмуляции тач-устройства на 375/390/430: фокус перетекает между карточками при медленной прокрутке и не мечется при быстрой; секции разворачиваются один раз; карусель примагничивается и не перехватывает вертикальную прокрутку; нижний лист закрывается жестом и не тянет страницу; долгое нажатие поднимает полосу без системного меню.
5. **Замер кадра** в Performance при 200+ карточках: прокрутка и смена фильтра одновременно. Это численный критерий для шага 16, а не впечатление.
6. В панели Rendering эмулировать `prefers-reduced-motion`, `prefers-reduced-transparency`, `prefers-contrast`, `forced-colors` и сверить с принудительными переключателями витрины — результат должен совпадать. При уменьшенном движении перетекания заменяются короткими перекрёстными затуханиями, но **не исчезают**: пользователь должен по-прежнему понимать, что состояние изменилось.
7. **Доказательство отсутствия регрессий:** открыть `/`, `/search`, `/zrodla`, `/konto`, `/box-materialu`, `/box-kontekstu` — они обязаны выглядеть в точности как раньше, **включая шрифт**: живые страницы остаются на IBM Plex, Montserrat туда не протекает.
8. `git diff --stat`: ожидаемый след — новые файлы в `packages/ui/src/kit/`, один новый маршрут, подпуть `./kit` в `packages/ui/package.json`, `+2` строки в `layout.tsx` (стили кита и переменная шрифта), `MotionRoot` в `providers.tsx`, правки документации. **`globals.css` должен показать ноль изменений**, `backend/` — ноль изменений. Иначе изоляция протекла.

Витрина работает на фикстурах и **не требует бэкенда** — Docker и Django здесь недоступны. Это ещё один довод за порядок «сначала библиотека»: главную без `/api/portal/config/` и `/api/feed/` проверить нельзя.

## Риски

- **Порядок подключения стилей.** Если `kit.css` окажется раньше `globals.css`, янтарное кольцо фокуса и `box-shadow: none` выиграют. Критерий приёмки шага 1 — карточка токенов с тенью и синим кольцом.
- **Случайная утилита Tailwind в компоненте библиотеки.** Один `className="bg-white"` возвращает элемент в слой перезаписи, и он начинает темиться от `--surface` вместо `--sc-surface`. Запрет пишем в шапке `kit.css` и в `docs/UI_KIT.md`.
- **Расползание объёма на живую главную.** Контролируется пунктом 5 проверки: ноль изменений в `globals.css`.
- **Node 24 + Next 14.2** — сочетание не проверялось; базовая сборка на шаге 0 отделяет это от наших правок, запасной вариант — Node 20 LTS.
- **Дропдаун внутри лент.** `.material-strip` и `.news-strip-track` имеют `overflow-x: auto` и обрежут непортализованную панель. На витрине не проявится; фиксируем как предусловие этапа 2.
- **`prefers-reduced-transparency`** поддержан неравномерно (Safari 17+, Chrome 118+, Firefox отстаёт). Запасной путь — непрозрачная поверхность, что строго лучше.
- **Отсутствие тестов**: регрессии ловит только сборка и ручной осмотр.
- Ассеты `public/illustrations/pastel/*` осиротеют на этапе 2. Не удаляем — существующий мусор, отдельная уборка.

- **Сплошное движение — главный риск этой работы.** «Анимируем всё» ломается двумя способами: технически (каждый `layout` это принудительное измерение, на сетке в 200 карточек наивное применение убивает кадр) и по ощущению (движение ради движения читается как медлительность). Оба лечатся дисциплиной, а не отказом: единые примитивы, короткие длительности, прерываемость, `layout="position"` где достаточно, и обязательный замер на шаге 11. Если замер покажет деградацию — сокращаем область `layout`, а не выразительность.

- **Montserrat без `latin-ext`** — самая дорогая мелочь: польская диакритика молча уедет в запасной шрифт, текст поменяет ширину и цвет, и заметить это можно не сразу. Критерий приёмки шага 1 включает проверку именно диакритики.
- **Montserrat шире IBM Plex Sans.** Длинные польские слова в узкой карточке `mini` могут переноситься хуже. Правим кеглем заголовка, а не шириной карточки, иначе поедет вся сетка. Фикстуры обязаны содержать реально длинные строки, иначе проблема всплывёт уже на живых данных.
- **`next/font` рядом с `@fontsource`.** В проекте появляется второй механизм подключения шрифтов. Это осознанно: старый остаётся для живых страниц, новый обслуживает библиотеку. На этапе 2, когда IBM Plex перестанет использоваться, импорты `@fontsource` удаляются — до тех пор в сборку входят оба, и это временно лишние килобайты.
- **Отскок на наведении** — сделан по просьбе владельца вопреки правилу «overshoot только после инерции». Держим значения маленькими и быстрыми; если при проводке мыши по сетке карточки начнут заметно дрожать, первым делом уменьшаем bounce ступени A, а не длительность.
- **Фокус при прокрутке на телефоне** может ощущаться как «дёрганье», если срабатывает на каждой карточке во время инерционной прокрутки. Поэтому смена фокуса подавлена выше порога скорости и срабатывает на замедлении; порог подбирается на устройстве, не в эмуляторе.
- **Лишнее касание на пути к материалу** (ступень B на телефоне). Осознанная плата за лестницу; проверяется вживую, запасной вариант — касание ведёт сразу в полный экран, предпросмотр по долгому нажатию.
- **Перетаскивание против горизонтальной прокрутки.** Полосы прокручиваются вбок, поэтому захват возможен только за ручку, а на тач-устройствах — долгим нажатием. Если перетаскивание начнётся с самой полосы, пользователь потеряет прокрутку внутри неё — это проверяется первым.
- **Порядок полос сохраняется только на устройстве.** Профильного поля под него в бэкенде нет, а контракты API мы не меняем. Интерфейс обязан говорить это прямо, иначе пользователь решит, что порядок привязан к аккаунту, и потеряет его на другом устройстве.
- **Раскрытие по наведению внутри лент** — самая тонкая часть. Копия карточки в слое-портале должна встать пиксель в пиксель поверх оригинала, иначе на передаче будет заметный сдвиг. Проверяется на крайних карточках ленты и при прокрученной ленте, а не только на первой. Если совмещение окажется ненадёжным, запасной вариант — отказаться от раскрытия **внутри лент** (оставив свечение и левитацию) и сохранить его только в обычных сетках, где обрезки нет.
- **App Router не анимирует выход маршрута.** Обходной приём с «замороженным роутером» ломается на обновлениях Next, поэтому он не берётся. Следствие честное: переходы между страницами анимируются только на вход. Основной сценарий продукта это не задевает, потому что «карточка → материал» вообще не навигация.

Отдельно — ловушки движения, каждая из которых ломает эффект тихо:

- **`router.push` вместо `pushState`** размонтирует дерево и убивает морфинг. Любой будущий рефактор, заменяющий `pushState` на `<Link>`-навигацию, ломает эффект целиком.
- **Потеря `?q=` в адресе** молча сбрасывает поиск пользователя через цепочку `PortalHome → Baza`.
- **`will-change` на `.material-box`** нельзя добавлять: 200 постоянно поднятых композиторных слоёв исчерпывают бюджет GPU на мобильном Safari и дают ровно те рывки, от которых мы уходим. framer-motion ставит и снимает его сам.
- **Анимация `backdrop-filter`** заставляет перерастрировать весь экран каждый кадр. Блюр включаем после завершения морфинга и снимаем перед выходом.
- **Условно смонтированный `<AnimatePresence>`** — причина номер один для «выход не анимируется». Постоянным должен быть контейнер, условным — ребёнок.
- **`startTransition` вокруг открытия портала** разведёт карточку и оверлей по разным коммитам, и морфинг стартует из неверной точки.
- **StrictMode в разработке** удваивает эффекты: без защиты по ref получаем две записи в истории на одно открытие, и «Назад» выглядит сломанным только в dev. Проверять и на продакшен-сборке.
- **`LazyMotion strict`** (экономия ~30kb) несовместим с прямым `motion.*` в существующем `ArticleModal.tsx`. На этом этапе не трогаем.
